# 小爱音箱播放集成

`/miot` 页面把小爱音箱接入 lxserver：可以选择 LX Music 用户的歌单或搜索歌曲，让音箱播放，而音频流由 lxserver 直接提供。在线歌曲依赖已启用的自定义源；本地曲库和已有缓存可直接播放。

## 工作原理

```text
/miot 页面
  └─(管理员密码) /api/miot/* ──► MiotService ──► 小米云 / 音箱 UBus
                                      │
                                      ├─ 读取 LX 用户歌单、收藏
                                      ├─ 本地曲库 → 服务器缓存 → 自定义源解析
                                      └─ 生成一次性 /api/miot/stream/<token>.<ext>
                                                         │
                                                    小爱音箱拉流
```

- 播放队列只保存歌单 ID 与索引；搜索结果属于临时队列，会随播放记录保存前 200 首。
- 下发给音箱的不是第三方直链，而是 lxserver 的短时令牌地址（默认 3 小时有效）。本地文件和服务器缓存直接由 lxserver 提供；在线歌曲由 lxserver 代理，并透传 `Range` 以支持拖动。
- `local_` 开头的歌曲从当前 LX 用户的本地曲库读取。在线歌曲优先命中服务器缓存；未命中时按音质候选依次调用自定义源解析（同平台会轮询所有支持该平台的自定义源）。原平台不可用或全部音质解析失败时，会跨平台搜索同曲（标题/歌手/时长严格匹配，每个平台只取最匹配的一版）继续尝试；只有本地、缓存、降音质、多 API 源、跨平台换源全部失败后，才会从歌单删除该歌曲。
- 音箱接受播放指令后仍未真正起播（典型是提示“没有版权/无可用音源”后停止）时，服务端会二次回读状态确认，然后把该曲从歌单删除并自动切到下一首，日志记为“音箱拉流失败（未起播）”；已确认起播后的中途停止沿用原有逻辑，不会误删。连续 3 首拉流失败会停止自动切歌，避免断网时一次清空歌单。
- 搜索同样是本地优先：先匹配当前 LX 用户本地曲库的标题、歌手和专辑，命中结果排在前面，剩余名额再由第一个有结果的可用音源补齐，并按“歌名+歌手”去重。
- 各音源搜索结果会附带 `vip` 标志（依据网易云 `fee`、QQ 音乐 `pay`、酷我 `payInfo.paytype`、酷狗 `Privilege/PayType`、咪咕标签）。VIP 歌曲在页面和播放区显示金色 `VIP` 徽标。
- 播放记录保存在 `data/miot.json`。服务重启后队列恢复为停止状态，不会自动继续播放。

## 前提条件

- lxserver 已设置管理员密码，正式环境不要使用默认的 `123456`。
- 已有可用的 LX Music 用户，并且该账号能看到目标歌单。
- 在线播放需要在 lxserver 中导入并启用了支持对应平台和音质的自定义源，与 Web 播放器共用同一套音源机制。
- 小爱音箱能够访问 lxserver 的推流地址。建议在设置中显式填写“对外地址（音箱访问）”，例如 `http://192.168.1.100:9527`；使用反向代理时填写音箱可达的外部地址。
- 小米账号已登录，账号下有受支持的小爱音箱。
- `data/` 目录可写，用于保存账号、设备、队列与口令配置。

## 快速开始

1. 在落雪播放器左侧菜单“本地音乐”下方点击“小爱音箱”，控制页会直接嵌入播放器内容区展示（也可单独打开 `http://服务器IP:9527/miot/`），输入后台管理员密码；播放器已登录管理员时会自动复用密码。
2. 在“小米账号”区域登录：
   - 默认“扫码登录”：用米家 App 或小米商城 App 扫描二维码，并在手机上确认；二维码过期后点击“获取 / 刷新二维码”；
   - 或切换“密码登录”，使用小米账号密码，按提示完成图片验证码或手机/邮箱二次验证；
   - 或切换“Token”，使用已抓取的 `userId` 与 `serviceToken` 手动登录（`ssecurity` 可选）。
3. 登录后同步设备，选择目标音箱，确认“托管”开关已打开。
4. 在“运行设置”中选择落雪用户、音质、对外地址和轮询间隔，保存设置。
5. 在“播放”中选择歌单或搜索歌曲，点击播放。首次播放会解析歌曲并下发推流地址。
6. 需要语音控制时，保持“启用小爱集成”和“语音口令监听”开启，用“语音测试”验证，再查看语音日志。口令表支持添加、编辑、删除和启停，也可一键恢复默认。
7. 想让落雪播放器直接使用小爱音箱时，在播放器顶部的“播放源”中选择目标音箱；切回“网页播放”即恢复浏览器出声。

`/miot` 是独立页面，请勿把 `ADMIN_PATH` 或 `PLAYER_PATH` 设置为 `/miot`，否则该页面不会生效。

扫码登录由后端完成：先以 `mijia` SID 获取二维码，轮询到 `passToken` 与 `userId` 后再换取 `micoapi` 的 `serviceToken`。单次轮询在服务端最多等待约 25 秒，超时只是继续等待，不会立即判定二维码过期；连续异常返回后才会让前端刷新二维码。

## 设置项

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 启用小爱集成 `enabled` | `true` | 服务启动时同步设备并开启语音监听；关闭后停止语音监听，不再自动同步设备，播放仍可在本页手动操作 |
| 落雪用户 `username` | 空 | 读取该 LX 用户的歌单、收藏与自定义源；留空时使用公开库（`_open`）可用的开放源 |
| 音质 `quality` | `320k` | 首选音质；不可用时按 lxserver 的音质候选顺序回退 |
| 对外地址（音箱访问）`public_base_url` | 空 | 下发给音箱的推流地址前缀；留空时按最近访问的 Host 或局域网 IPv4 推断 |
| 语音口令监听 `voice_enabled` | `true` | 轮询小爱对话记录并执行匹配到的口令 |
| 对话轮询间隔（秒）`poll_interval_sec` | `2` | 单位秒，范围 1–30；连续失败时自动退避，最长 60 秒 |
| 自动下一首 `auto_next` | `true` | 一首结束后按队列和播放模式续播；关闭后结束即停止 |
| 播放时缓存到落雪 `cache_on_play` | `false` | 远端歌曲推流时异步写入服务器缓存，下次优先使用缓存 |
| VIP 歌曲自动下载 `vip_auto_download` | `false` | 播放远端 VIP 歌曲时异步下载到当前用户的下载目录（音乐库），之后播放优先命中本地；歌单同步数据缺少 `vip` 字段时也按 VIP 处理，明确标记为免费的歌曲不下载 |
| 默认歌单 ID `default_playlist_id` | `default` | 语音“播放歌单”未指定名称时使用的歌单 |
| 播放中保持音箱灯效 `keep_light` | `false` | 推流时尽量保持音箱灯效，实际效果按机型而定 |
| 播放前语音播报歌名 `announce_song` | `false` | 播放成功后用 TTS 播报歌曲名（点播页面默认关闭播报） |
| AI分析（内置AI的音箱可用其他音箱自测）`ai_recommend_enabled` | `false` | 一个开关同时控制自动推歌与语音指令解析：点播单曲时先判断歌曲类型再续播同类，规则口令无法识别时交给 AI 解析意图；存在未清除的 AI 错误时无法开启 |
| AI 每日额度（次）`ai_daily_limit` | `60` | 自动推歌与意图解析共用的每日 AI 调用上限，范围 1–200；调低后当天已用额度不会被重置 |
| 连续失败阈值（次）`ai_failure_threshold` | `3` | 统计窗口内连续未响应或超时达到该次数才自动关闭 AI，范围 1–10；登录或 Token 失效、设备缺少必要字段仍会立即关闭 |
| 失败统计窗口（分钟）`ai_failure_window_min` | `10` | 连续失败计数的有效间隔，范围 1–60；两次失败间隔超过窗口会重新计数，任何一次成功回答（包括“无关”）都会清零 |

对外地址的推断顺序为：设置值 → 最近一次非本机访问的 Host → 本机局域网 IPv4 + 主服务端口。反向代理、HTTPS 或跨网段使用时必须显式填写，否则音箱可能拿到无法访问的地址。

## 播放与队列

- 队列来源为 LX 用户的“试听列表”“我的收藏”和自定义歌单；搜索会生成临时的 `miot_search` 队列。
- 播放模式支持顺序播放 `order`、列表循环 `loop`、单曲循环 `single`、单曲播放 `singlePlay` 和随机播放 `shuffle`。
- 自动续播依赖歌曲时长定时器；同时每 15 秒回读一次设备状态。设备提前停止时会尝试重新推流当前歌曲；设备暂停或停止时会同步本地状态。
- “上一首”在当前进度超过 5 秒时回到本曲开头；列表循环模式下第一首的上一首是最后一首。
- 收藏操作写入当前用户的“我的收藏”歌单，并生成歌单快照。
- 不喜欢类口令只作用于当前播放歌曲，并同步到落雪“我的收藏”的三个列表：歌曲写入不喜欢快照，歌手与专辑分别写入 `dislike/library/artists.json`、`dislike/library/albums.json`。歌曲按“歌名@歌手”记录当前版本，只影响这位歌手演唱的这首歌，不会连带屏蔽整首歌或整个歌手。合唱歌曲会按分隔符拆开，逐个加入所有歌手。新增不喜欢成功后自动切到下一首；取消不喜欢只移除列表项，不切歌。
- 升级后第一次加载配置时，会一次性补齐缺失的“不喜欢”默认口令；已有同类型口令（包括用户改过关键词或禁用的）不会被覆盖，删除后也不会再次补回。
- 音量以设备回读值为准；语音调节音量时不会重复下发音量指令，避免双重调节。
- 睡眠定时支持按分钟或按歌曲数停止，到期后停止播放并 TTS 提示。

## AI 分析（自动推歌与指令解析）

页面上的“AI分析（内置AI的音箱可用其他音箱自测）”是**唯一开关**，同时启用两条能力：自动推歌和语音指令解析。两者共享同一个可配置的每日额度（默认 60 次，可在页面“AI 每日额度”中调整，范围 1–200）、同一个错误记录和同一套连续失败阈值（默认 10 分钟内连续 3 次，均可调整）；内置 AI 的音箱可直接使用，其他机型也可以开启后自行测试是否支持。

### 自动同类推荐

开启后，语音点播单曲（“播放歌曲”“播放歌手”）只把搜索第一名作为种子入队，播放器在种子播完前预取同类推荐并追加到队列，不再把同名翻唱全部塞进队列导致单曲循环。手动播放歌单、搜索后点播等入口不受影响。

- 首次遇到新歌时，通过小米云 `execute-text-directive` 让小爱朗读一句分类询问，例如“歌曲类型判断：数鸭子，儿歌。只回复一句话：少爷将继续为您推荐（类型），不要解释。类型只能是：儿歌、流行……”，再轮询对话记录，从大模型回答（如“少爷将继续为您推荐儿歌”）里提取封闭类型；约 25 秒拿不到回答按超时处理。
- 类型结果按“歌名 + 歌手 + 专辑”缓存 30 天，同一首歌之后不再询问；每日调用次数受页面“AI 每日额度”限制（默认 60 次，范围 1–200）。该能力需要 `xiaomiio` 的 serviceToken，服务会用保存的 `passToken` 懒换取，并在过期前 3 小时自动续期。
- 推荐来源依次为：网易云相似歌曲 → 酷狗对应类型榜单 → 类型关键词搜索（儿歌会追加“童谣”）→ 同歌手其他作品。会过滤与种子同名的翻唱和队列中已有歌曲。
- 分类询问会短暂打断当前播放，回答后自动恢复；如果歌曲已经自然结束则不会重播种子。

### 语音指令解析

规则口令仍然优先：完整命中的口令（如“下一首”“播放歌曲 晴天”）直接执行，不产生 AI 延迟。只有以下情况才会把原话交给 AI 解析：

- 规则完全没有匹配，但原话通过本地音乐域预判（明确的音乐名词、已配置的口令词或播放动作）。
- “播放歌曲”“播放歌手”只匹配到半截口令、缺少名称参数。
- `set_play_mode` 的后缀不是“模式/播放模式”。

调用 AI 前会先做本地音乐域预判：天气、新闻、故事、闹钟、提醒、聊天、视频、家电控制等与歌曲无关的话术直接忽略，不会产生 AI 请求，也不消耗每日额度。预判只决定“是否值得交给 AI”，不做本地意图识别；包含“歌、曲、音乐、榜单”等明确音乐名词或已配置口令词的原话会放行。

AI 提示词由页面“语音”口令表动态生成（`{commands}` 占位符），并采用两段式判断：先判断原话是不是歌曲或播放器操作，不是则只回答“无关”；是则只能从已启用的口令词中选一个，输出“口令词”或“口令词：参数”。除配置口令外，保留“随机听歌”（`play_random`）和“播放热门”（`play_hot`）两个 AI 扩展动作，参数只能是页面列出的歌曲类型，也可以留空。自定义提示词中没有 `{commands}` 时，服务会自动把口令表插入到用户原话之前。回答“无关”只记日志、不执行；回答无法识别也只记日志并跳过，不计为 AI 故障。解析结果会再次走与规则口令相同的执行逻辑。

歌单与榜单查询优先使用落雪在线音源，失败后再回退本地：

- `play_playlist`：带歌单名时优先查找并播放本地歌单；本地不存在或为空时才按已启用音源搜索在线歌单并载入歌曲；“我的收藏”“试听列表”始终按本地歌单处理；不带名称时使用默认歌单。
- `play_chart`：支持“播放榜单 飙升榜”“播放热歌榜”“播放儿歌榜”等，榜单名可带平台前缀（如“酷狗热歌榜”）；先聚合已启用音源的榜单列表按名称匹配并拉取歌曲，失败后依次回退到同名本地歌单、本地曲库类型/关键词筛选，最后随机本地歌曲。不带榜单名时使用“热歌榜”。AI 关闭时，“播放飙升榜”这类常见榜单口令也能直接命中。

随机听歌与热门播放不依赖第三方新接口：

- `play_random`：按类型优先从本地曲库随机抽取，不足时用酷狗对应类型榜单补齐；未知关键词用搜索补齐；无类型时从本地曲库随机，并用热门榜单补足，最后切换为随机播放模式。
- `play_hot`：指定类型时使用酷狗对应类型榜单（无类型使用 TOP500 榜单），否则先按关键词搜索、再用“关键词+热门”兜底，最多取 20 首。

### 风控与错误处理

- 每次 AI 调用（分类或意图解析）都计入同一个可配置的每日额度（默认 60 次，范围 1–200）；额度耗尽时仅跳过 AI，不影响规则口令与已有的兜底推荐，也不会关闭开关。调低额度不会重置当天已用次数，调高额度会立即生效。
- 同一台设备同一时间只允许一个 AI 询问，避免两条指令的对话记录互相污染。意图解析遇到设备正忙时直接跳过；分类最多等待 15 秒。
- 失败分两类处理。超时、网络抖动、云端未返回内容等“未响应”类错误只会累计连续次数：在配置的统计窗口（默认 10 分钟）内未达到阈值（默认 3 次）时保持 AI 开启，记录 `AI 暂时未响应` 事件并等待下次重试，不写错误记录、不打断播放。达到阈值后才写入 `data/miot.json` 错误记录、自动关闭统一开关并在音箱播报摘要，页面需先点“清除错误记录”才能重新开启。
- 登录或 Token 失效、账号不存在、设备缺少 `miotDID`/硬件型号等必须人工处理的错误会立即关闭 AI；每日额度耗尽、设备正忙、回答无法识别不计为失败。清除错误、重新开启开关、修改阈值/窗口都会清零连续计数；任何一次成功回答（包括“无关”和分类结果无法归类）也会清零。
- 分类失败后仍按启发式类型走兜底推荐；意图解析失败时不执行任何猜测指令。
- 内部 AI 提问带有“歌曲类型判断”“指令解析”标记，语音监听会跳过这些对话，避免把发给小爱的提示词当作用户口令执行。
- 设备对话记录会写入 AI 事件，便于核对调用与返回：`AI 分类请求`、`AI 分类返回`、`AI 同类推荐`、`AI 指令解析请求`、`AI 指令解析返回`、`AI 暂时未响应`、`AI 异常`。其中 `AI 暂时未响应` 标注连续次数并保持开启；`AI 异常` 表示达到阈值或需要人工处理的错误，已自动关闭。

## 播放器播放源

播放器顶栏登录按钮左侧有一个“播放源”选择器，用于决定落雪 Web 播放器从哪里出声：

- “网页播放”：默认模式，浏览器正常播放。
- “小爱 · 音箱名”：主播放器保持播放进度但本地静音，每首歌曲通过 `POST /api/miot/play` 推送到当前可用音箱。暂停/继续、音量和上下曲会与音箱同步；拖动进度、倍速和音效暂不同步。
- 目标音箱优先取 `/miot` 页面最近选择的设备，否则取第一台托管设备。选择时会用后台管理员密码校验；未验证密码会先弹窗，没有可用设备则提示并跳到“小爱音箱”页面。
- 推送失败（设备离线、解析失败等）会自动切回网页播放并恢复本地声音；切回网页播放时会向音箱发送停止指令。
- 选择结果保存在浏览器 `localStorage` 的 `lx_play_source` 中，刷新后自动恢复；如果目标设备已不可用，会回退到网页播放。

## 语音口令

语音监听会定时拉取每台托管且开启语音的设备最近的小爱对话记录，按时间戳去重后匹配口令。启动后的第一条记录只作为基线，不会执行历史指令；拉取失败会指数退避。

匹配规则：

- 先做关键词包含匹配，命中多个时取最长关键词，长度相同时按口令类型优先级决定。
- 关键词至少 3 个字符时，允许最多 4 个插入字符的跳字模糊匹配。
- “播放歌曲”“播放歌手”“播放歌单”等搜索口令之后的内容作为名称参数，例如“播放歌曲 晴天”。
- “播放第 N 首”和睡眠定时支持中文数字，例如“播放第三首”“半小时后停止”。
- 即使自定义口令删除了停止类关键词，内置停止词仍可作为兜底。
- 开启 AI 分析时，规则无法识别的音乐类说法会交给 AI 解析意图；完整命中的规则口令仍直接执行，不经过 AI。
- 语音唤醒可能打断流播放；音量、收藏、取消不喜欢、睡眠定时等不改变播放内容的口令执行后，会检查并恢复当前播放；新增不喜欢会切到下一首，并在播报后恢复新歌曲的播放。

默认口令：

| 类型 | 参数 | 默认关键词 |
| --- | --- | --- |
| `play_playlist` | — | 播放歌单、放歌单、播放列表 |

| `set_play_mode` | `shuffle` | 随机播放、随机模式 |
| `set_play_mode` | `single` | 单曲循环、循环播放这首 |
| `set_play_mode` | `singlePlay` | 单曲播放、只播放这首、播完这首停止 |
| `set_play_mode` | `loop` | 列表循环、循环播放 |
| `set_play_mode` | `order` | 顺序播放 |
| `set_volume` | `absolute` | 设置音量、音量调到、音量、声音、声音调到 |

| `dislike_artist` | `add` | 不喜欢这个歌手、不喜欢这位歌手、不喜欢当前歌手 |

请求体示例：

```json
{
  "commands": [
    { "type": "play_song", "keywords": ["播放歌曲", "我想听"], "enabled": true },
    { "type": "set_volume", "keywords": ["音量调到"], "param": "absolute", "enabled": true },
    { "type": "next", "keywords": ["下一首", "切歌"], "enabled": true }
  ]
}
```

`POST /api/miot/voice/commands/reset` 恢复默认口令表。语音测试接口默认只做匹配演练，传入 `execute: true` 才会实际操作音箱。

## HTTP API

除流地址外，所有接口都要求请求头 `x-frontend-auth` 等于后台管理员密码，响应为 JSON。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/miot/status` | 设置、AI 分析状态、账号安全信息、设备列表、推流地址、口令数量和 LX 用户 |
| GET | `/api/miot/ai` | AI 分析状态：`enabled`（统一开关）、`error`、`cachedTypes`、`dailyCount`、`dailyLimit` |
| POST | `/api/miot/ai/clear-error` | 清除 AI 错误记录，返回最新的 AI 分析状态 |
| GET | `/api/miot/devices` | 设备列表及每台设备的播放视图 |
| POST | `/api/miot/settings` | 更新设置，字段见上表 |
| GET | `/api/miot/settings` | 读取设置（落雪设置页的「VIP 歌曲自动下载」开关用它同步状态） |
| POST | `/api/miot/login/qrcode` | 获取小米账号登录二维码，返回 `loginId`、`qrcodeUrl`、`loginUrl` |
| POST | `/api/miot/login/qrcode/poll` | 轮询扫码状态：`loginId`；返回 `waiting` / `success` / `expired` / `failed` |

| POST | `/api/miot/login/token` | 手动 Token 登录：`userId`、`serviceToken`、`ssecurity`、`username` |
| POST | `/api/miot/logout` | 退出小米账号：`accountId` |
| POST | `/api/miot/devices/sync` | 同步账号设备：`accountId` |
| POST | `/api/miot/device` | 更新设备开关：`accountId`、`deviceId`、`managed`、`voice_enabled`、`play_mode`、`volume` |

| GET | `/api/miot/voice/log?accountId=&deviceId=` | 查询最近语音记录，最多 100 条 |

`action` 支持：

| action | value | 说明 |
| --- | --- | --- |
| `pause` | — | 暂停；部分机型会升级为停止 |
| `resume` | — | 继续播放 |
| `stop` | — | 停止播放 |
| `next` / `previous` | — | 上一首 / 下一首 |
| `replay` | — | 重新播放当前歌曲 |
| `volume` | 0–100 | 设置音量 |
| `sync-volume` | — | 回读设备音量 |
| `mode` | `order`、`loop`、`single`、`singlePlay`、`shuffle` | 切换播放模式 |
| `favorite` | `add` / `remove` | 收藏或取消收藏当前歌曲 |

流地址使用 18 字节随机令牌，有效期 3 小时，支持 `GET`、`HEAD`、`OPTIONS` 和 `Range`。令牌不存在返回 404，过期返回 410，过期记录每 10 分钟清理一次。

## 安全与存储

- 小米账号的 `userId`、`serviceToken`、`passToken` 和设备信息保存在 `data/miot.json`。该文件同时包含设置、播放记录和口令，应像配置文件一样保护并纳入备份。
- 管理 API 使用管理员密码；页面只把密码保存在当前标签页的 `sessionStorage`。通过公网访问时请使用 HTTPS，并限制 `/miot` 和管理 API 的来源。
- 推流地址是 bearer 凭证：任何拿到 URL 的客户端都能在有效期内拉取对应歌曲，没有 IP 绑定。不要把日志或截图中的完整流地址公开。
- `/miot` 静态页面本身可访问，但所有配置和播放接口都需要管理员密码。
- 语音控制面向能唤醒音箱的人：任何能对音箱说话的人都可以操作当前队列、音量和收藏。仅在可信设备上开启语音监听。
- 开启 AI 分析后，分类会把歌名与歌手、意图解析会把用户原话作为文本指令发送到小米云，并由音箱朗读；不要对包含敏感信息的曲目标题或语音开启该功能。
- 如果管理员密码或小米账号失效，相关接口会返回错误；Token 临近过期时会尝试用 `passToken` 自动刷新，刷新失败需重新登录。

## 限制

- 只支持已登录的小米账号和开放的小爱 UBus 能力；不同固件、机型的播放接口和状态字段存在差异，部分机型可能无法暂停、回读进度或使用 TTS。
- 语音监听依赖小爱对话记录接口；账号或固件不提供该记录时，语音功能不可用，只能手动控制。
- AI 分析依赖小爱的大模型回答；偶发未响应会按配置的阈值重试，连续失败达到阈值或登录失效才会关闭，关闭后仍可继续使用不带 AI 的规则口令与启发式兜底推荐。内置 AI 的音箱可直接使用，其他机型可在页面自行测试。
- 不支持歌词、封面、转码和音效；音质取决于自定义源实际返回的链接。音质回退失败时可能播不了该歌曲。
- 服务器重启会丢失内存中的自动续播、状态轮询和睡眠定时器；队列恢复后需要手动继续播放。
- 同一台音箱共用一个播放队列，多个页面或多个管理员看到的是同一状态；在别处用遥控器或小爱原生播放会与队列状态不一致。
- 单曲循环和自动下一首依赖服务端定时器；服务停止或设备长时间离线后不会继续推进队列。
